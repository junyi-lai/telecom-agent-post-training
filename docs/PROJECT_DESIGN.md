# 项目设计

本文集中说明实验问题、冻结数据、数据构建、训练设置和评测口径。实现细节可在 README 的代码阅读路线和源码注释中继续追踪。

## 1. 实验问题

项目研究：在训练任务、SFT token 预算、GRPO 轨迹预算和评测条件一致时，围绕失败任务分配数据，是否比按普通顺序分配更有效？

实验环境使用固定 tau2-bench 提交中的电信客服域。它提供明确政策、用户侧和 Agent 侧工具、可变数据库状态与确定性任务断言，适合检查多轮工具型 Agent 的真实完成情况。

学生模型使用官方发布的 `Qwen/Qwen3.5-2B` checkpoint。上下文长度固定为 32K，关闭学生模型的 thinking。学生模型通过 vLLM 提供工具调用能力。

## 2. 模型角色

| 角色 | 模型 | 职责 | 可见信息 |
| --- | --- | --- | --- |
| 学生 | Qwen3.5-2B | 生成动作与工具调用 | 完整对话、系统指令和工具定义 |
| 用户模拟器 | DeepSeek Flash | 按客户设定回答 | 客户场景和用户工具结果 |
| 离线教师 | DeepSeek Flash | 提供成功示范 | 可在验证前读取任务真值 |
| 最终判定 | tau2 确定性断言 | 比较数据库与任务状态 | 环境真值 |

教师和用户模拟器不是同一 Prompt：前者提供线下示范，后者只提供交互反馈。教师不参与在线 GRPO rollout。最终结果不依赖另一个 LLM 的开放式主观评分。

## 3. 冻结数据

| 数据划分 | 任务数 | 基线轨迹数 | 用途 |
| --- | ---: | ---: | --- |
| Smoke | 5 | 10 | 基础设施验证 |
| 官方训练 | 64 | 256 | 训练 |
| 扩展训练 | 100 | 400 | 训练 |
| 训练池 | 164 | 656 | 基线与数据构建 |
| 开发集 | 10 | 0 | checkpoint 选择 |
| 冻结测试集 | 40 | 120 | 最终模型比较 |

训练池共 164 个任务。开发集、测试集与训练池不存在完全相同的故障签名，测试任务不参与 SFT、GRPO 或 checkpoint 选择。

## 4. 数据生产

### 基线采集

学生模型对 164 个训练任务各执行 4 次：

| 问题类型 | 回合数 | 严格成功率 |
| --- | ---: | ---: |
| MMS | 284 | 0.0% |
| 移动数据 | 252 | 14.3% |
| 服务 | 120 | 41.7% |
| 总计 | 656 | 13.1% |

其中 86 条严格成功，570 条以轮数上限终止，另有 15 次非法工具调用失败和 12 次重复调用失败。训练任务上的 13.1% 描述的是数据生产难度，不能和冻结测试成功率直接比较。

### 教师纠错

所有至少失败一次的 155 个任务进入教师纠错。每个任务最多执行 2 次，单次最多 60 步。只有独立通过 tau2 严格评测的教师轨迹才能进入 SFT。

最终得到 310 条教师轨迹：302 条严格成功、6 条达到轮数上限、2 条基础设施错误。与 86 条基线成功合并后，有效 SFT 候选池共 388 条成功轨迹。

## 5. SFT 数据

候选池共有 313,578 个 assistant token。为让两组选择真正不同，每组固定使用 160K assistant-token 预算，分两个阶段选择。

### 两阶段选择

1. **任务覆盖**：为 164 个训练任务各选择一条成功示范。优先选择 assistant token 较少的轨迹；相同时按稳定 ID 排名，为第二条轨迹保留预算。
2. **剩余预算**：普通组按稳定随机顺序选择第二条；失败感知组排除普通组第二遍的全部消息指纹后，按失败类型轮转。

不变量：

- 每个实验组中，源样本 ID 和消息指纹最多出现一次；
- 完全相同的历史轨迹在采样前删除；
- 每个 `task_id` 最多 2 条；
- 必需任务无法覆盖时直接失败，不静默导出不完整数据；
- 不复制消息行来凑满 token 预算。

| 实验组 | 样本数 | assistant token | 覆盖任务 | 1 条任务 | 2 条任务 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 普通组 | 227 | 159,949 | 164/164 | 101 | 63 |
| 失败感知组 | 225 | 159,960 | 164/164 | 103 | 61 |

两组共享 164 条覆盖示范，普通组独有 63 条，失败感知组独有 61 条。共享部分包含 100,734 个 assistant token，约占每组预算的 63%。因此实验比较的是覆盖核心相同后，增量数据如何分配。

SFT 使用 LoRA，rank 32、alpha 64、学习率 `1e-4`、2 个 epoch、最大长度 32,768。训练 loss 只计算助手回复与工具调用，用户消息和工具结果作为上下文。

## 6. RL 数据与奖励

GRPO 每步执行：

```text
8 个 Prompt × 每组 8 条策略轨迹 = 每步 64 条轨迹
```

两组都使用 `train_batch_size=8`、`rollout.n=8` 和 75 个 optimizer step。普通组 RL 训练 Prompt 有 164 行，每任务一次；失败感知组有 328 行，先覆盖全部任务，再追加 164 条确定性的加权重复。行数差异调整任务采样频率，不改变每步轨迹预算。

主奖励是 tau2 严格成功。过程奖励包含有界的环境进度、政策违规、非法工具调用、重复动作和提前退出项；奖励必须确定性、可解释，并且不依赖学习型奖励模型。

两组原则上使用相同 profile。正式训练冻结为 75 步；不要把 75 个优化步与单条评测对话的 100 轮上限混为一谈。

## 7. 评测协议

最终评测只使用 40 个冻结任务。每模型运行 seeds 300/301/302，每模型 120 条轨迹。同一任务的三个 seed 是该任务簇内的重复测量，不是三个独立样本。

学生模型使用贪心解码。用户模拟器使用温度 0.7；每个评测 seed 同时作为环境随机性和用户模拟器的 seed，使任务、环境和模拟客户行为一起变化。

统计顺序：

1. 计算每个模型在 40 个任务上的三 seed 平均严格成功率；
2. 对齐两个模型完全相同的 40 个任务 ID；
3. 计算任务级差值；
4. 执行 10,000 次任务簇配对 bootstrap；
5. 报告平均差、95% 区间及方向，不做多重比较校正。

开发集只有 10 个任务，用于比较约第 1、2 个 epoch 的 checkpoint。选择超参数前不得访问 40 个冻结测试任务。

## 8. 复现入口

安装与测试：

```bash
bash scripts/setup_inference.sh
make download-model
make test
```

主仓库不保存 tau2-bench 和 veRL 的第三方源码。推理脚本下载固定版本的 tau2-bench；`scripts/setup_training.sh` 下载固定版本的 tau2-bench 与 veRL，并应用仓库中的补丁。这样既能保持可复现，又避免把两个独立仓库及其 Git 历史混入主项目。

`make download-model` 从 Hugging Face 下载固定 revision 的 Qwen3.5-2B，并校验权重 SHA256；已有模型时可执行 `.venv/bin/python scripts/download_model.py --verify-only` 离线检查。

仓库已经包含原始基线与教师结果、归一化轨迹以及 SFT/RL 训练文件，可以直接开始训练：

```bash
ARM=uniform make train-sft
ARM=failure_aware make train-sft
ARM=uniform make train-grpo
ARM=failure_aware make train-grpo
```

需要从任务环境重新采集时，再执行完整数据管线：

```bash
make collect
make normalize
make teacher
make normalize-teacher
make dataset
make rl-dataset
```

采集文件、训练文件、字段说明和 SHA256 校验见 [数据说明](../data/README.md)。

评测：

```bash
MODEL_LABEL=base VLLM_BASE_URL=http://127.0.0.1:8011/v1 \
  EVAL_SEEDS="300 301 302" CONCURRENCY=8 \
  bash scripts/evaluate_tau2.sh
```

更多命令由 `Makefile` 和 `scripts/` 提供。训练数据与最终报告随 Git 提供；模型权重、checkpoint、评测原始轨迹、日志和其他可生成产物仍不进入仓库。
